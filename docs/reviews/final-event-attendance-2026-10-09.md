The migration adds three private invoker helpers (row formatting, read-only canonical identity resolution, attendance operation), a retry index in the existing private audit table, one integration-secret native wrapper, and one service-only web wrapper. It adds no new attendance table and no public table grants. Both public wrappers use an empty search path. Anonymous users cannot reach the core or admin wrapper; the scoped native wrapper verifies the existing protected bridge secret first. Web staff derive actor from verified Supabase Auth and `user_roles.admin`; native staff derive actor from callable Auth and an Admin SDK profile role plus disabled-account check.

The operation locks the per-person registration and entitlement, validates active admission entitlement and member status, and sets only `checked_in_at` plus update time. It never calls the existing identity-link operation because that operation claims/activates access. Trusted Firebase Admin Auth email can resolve a unique verified canonical member immediately without claiming access or waiting for the scheduled sweep. Wrong email, another account's identity, missing identity, multiple historical seats, and revoked/suspended admission return staff help. Manual arrival supports a canonical seat without an app identity.

Undo requires a staff reason and the required `expectedCheckedInAt` ISO timestamp from the displayed arrival, and audits the previous timestamp. The timestamp must retain the original microseconds; web should pass the original response string unchanged. The operation compares it under the seat/entitlement lock and rejects a stale first undo with `needs_help` / `attendance_changed_since_request`. Missing or invalid timestamps fail validation. Applied undo retries with the same correlation and original timestamp remain idempotent. Legacy `registration_state=checked_in` transitions to `claimed` when cleared to satisfy the existing schema constraint; normal arrival preserves registration/claim/access state. Correlation IDs replay without duplicate audit or mutation. Successful check-in replay must pass current admission eligibility and QR identity revalidation under the normal seat/entitlement/member/identity locks. Revoked admission or identity can never replay a positive check-in. If attendance changed after the original request, a retry returns `needs_help` / `attendance_changed_since_request` with the current row, preserving a later re-arrival.

Firebase: additive AI callable `formulaAttendance` in `us-central1`, using the three existing Formula bridge secrets. Request actions: `list`, `resolve`, `check-in`, `undo`, `history`. Event is bounded to `formula-2026`; page sizes are 100 (history 50). QR confirmation revalidates trusted UID+Auth email against the selected registration. The existing networking callable is untouched.

Web: extend existing `formula-admin-attendees` Edge Function with `attendance-list`, `attendance-check-in`, `attendance-undo`, `attendance-history`. Existing snapshot/upsert/access actions remain compatible. New actions call `formula_admin_attendance` after the existing real Auth/admin gate; caller-supplied actor and QR/email data cannot enter the canonical operation.
